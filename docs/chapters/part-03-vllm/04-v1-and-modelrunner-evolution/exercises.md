# 3.4 练习与参考答案

[正文](README.md) · [实验手册](lab.md)

先手算，再运行代码。涉及上游实现的题目，都以本节的固定提交为准。

## 1. “开启 V2”说清楚了吗

有人写实验记录：“开启 V2，比 V1 更快。”至少缺少哪些信息？

<details><summary>参考答案</summary>

缺少引擎架构、runner 实现、准确提交、平台、模型、负载、图模式及实际命中状态。MRV2 位于 V1 引擎内部，不是 vLLM V2 引擎。若两个记录来自不同版本，差异还混入其他变更；应先在同一份支持两条 runner 路径的提交上对照，并统一计时边界与正确性标准。

</details>

## 2. 换序后的 gather

状态池 `[A,B,C]` 的已计算长度是 `[2,3,0]`。本轮请求顺序 `[C,A]`，其映射和收集到的长度是什么？

<details><summary>参考答案</summary>

映射为 `[2,0]`，收集长度为 `[0,2]`。持久状态仍为 A、B、C；本轮第 0 条请求是 C，却占状态行 2。不能把 batch 行 0 当作状态行 0。

</details>

## 3. 换序后的 scatter

沿用上一题，本轮 C 处理 2 个 token，A 处理 1 个。更新后按 A/B/C 排列的长度是什么？如果直接更新第 0、1 行会怎样？

<details><summary>参考答案</summary>

正确结果 `[3,3,2]`。当前增量 `[2,1]` 要分别写回状态行 `[2,0]`。错误地写回 `[0,1]` 会得到 `[4,4,0]`，C 没有推进，没参与本轮的 B 却被推进。这是归属错误，计算增量本身没有错。

</details>

## 4. 批量校验为什么要先于修改

一次 `advance` 有两条请求：第一条增量合法，第二条会超过已知 token 长度。为什么不边遍历边改状态？

<details><summary>参考答案</summary>

若改完第一条才在第二条报错，这一批操作就部分生效，调用方很难判断能否重试。课程先验证全部增量，再统一写入，失败时保持状态不变。这是同步教学对象的原子性约束，不等于实现了跨设备事务或异步取消机制。

</details>

## 5. 同一行号还能不能使用

B 原在行 1，释放后 D 也在行 1。旧 step 持有索引 1，为什么索引不越界仍可能错误？generation 能解决所有并发问题吗？

<details><summary>参考答案</summary>

索引只标识存储位置，不证明当前拥有者还是 B。教学实现同时核对请求 ID 和分配代际，拒绝旧 step。generation 是额外教学保护，上游并无本节所声明的同名字段；它也不能取代设备事件、缓冲寿命和流依赖等并发约束。

</details>

## 6. 抢占恢复时的三个长度

原始 prompt 长度 6，已经生成 2 个 token，随后抢占并重算全部已知历史。恢复时 prompt、prefill、total 长度如何理解？能否认定状态槽位不变？

<details><summary>参考答案</summary>

这个场景中原始 prompt 为 6，恢复输入为 8，已知总长度为 8。重新计算的输入可能包含生成历史，不仅是原始提示。固定 MRV2 会释放抢占请求的执行侧状态，恢复时重新分配，不能承诺槽位不变。引擎请求仍可继续存在，执行侧移除不等于对用户报告完成。

</details>

## 7. 打包三次修改

对 `4×8` int32 表，写 `(0,1,[4,5])`、`(2,3,[7])`、`(3,0,[8,9,10])`。写出四个打包数组和逻辑字节数。

<details><summary>参考答案</summary>

`indices=[0,2,3]`，`starts=[1,3,0]`，`contents=[4,5,7,8,9,10]`，`cumulative_ends=[2,3,6]`。逻辑载荷为 `(6+3×3)×4=60` 字节，整表为 `4×8×4=128` 字节。不包含对齐、kernel 启动或传输开销，也不能推出真实加速比为 128/60。

</details>

## 8. 两次重叠写能否“后写覆盖”

同一批中，先 stage `(0,1,[4,5])`，再 stage `(0,2,[9])`。Python 调用次序能否保证设备最终第 2 列为 9？

<details><summary>参考答案</summary>

不能仅据 Python 顺序推断并行写入顺序。两个更新都写第 0 行第 2 列，若同一 kernel 的不同 program 无规定的顺序，结果就不能解释为稳定的“后写覆盖”。课程拒绝这个输入。若业务确需覆盖，应在提交前合并冲突，或使用有明确依赖关系的多阶段操作并核对实现。

</details>

## 9. 快照复制的收益与代价

共享列表从 `[3,7]` 改为 `[9,7]` 后才被消费者读取。为什么快照能保留旧值？又多付出了什么？

<details><summary>参考答案</summary>

快照使用独立存储，之后修改原列表不影响快照。代价包括复制工作和额外存储。真实 pinned 临时副本还需维持到设备读完，不能立即复用。课程只演示所有权关系，没有模拟 pinning、DMA、流或事件，也没有测这项代价。

</details>

## 10. 元数据和采样行的展开

状态行 `[2,0]` 的 C 为 `[7,4]`，本轮 q 为 `[1,3]`。写出 Query 边界、positions、seq_lens。如果对应采样行数也是 `[1,3]`，再写出采样状态映射。

<details><summary>参考答案</summary>

边界 `[0,1,4]`；positions `[7,4,5,6]`；seq_lens `[8,7]`；展开的状态行 `[2,0,0,0]`，请求内部位置 `[0,0,1,2]`。本轮输入行数和采样行数在这个题目中恰好相同，不代表一般情况下必须相等。

</details>

## 11. Gumbel 等价关系的条件

为什么固定同一组噪声时 `argmax(z+g)` 等于 `argmax(log_softmax(z)+g)`？能否据此跳过 temperature、top-p 或惩罚？

<details><summary>参考答案</summary>

同一行的 `log_softmax(z)` 相比 z 只减去共同常数 `logsumexp(z)`，不会改变加同一组噪声后的大小关系。温度、截断与惩罚会改变目标分布，不是共同减常数，不能跳过。固定噪声代数测试也不证明两套 RNG 的流相同；greedy 另有语义，不应加噪声。

</details>

## 12. 返回两个 logprob 的分母

logits 为 `[2,1,0,-1]`，只返回前两个候选。为什么它们的概率和不是 1？把这两个 logits 单独 softmax 会造成什么变化？

<details><summary>参考答案</summary>

完整词表仍给另外两个 token 分配概率；前两项只是原分布的子集，概率和约为 0.8808。它们的 logprob 约为 -0.44019 与 -1.44019。只在 `[2,1]` 上归一化会得到另一个两候选分布，logprob 约为 -0.31326 与 -1.31326，不能当作原分布的报告值。

</details>

## 13. 三个图执行决定

桶为 `[1,2,4,8]`，完整图已捕获 `{4}`，配置 `FULL_AND_PIECEWISE`。分别判断 `[1,1,1]`、`[1,3]` 和 `[9]`。

<details><summary>参考答案</summary>

普通 decode `[1,1,1]` 使用 FULL，实际 3 个 token，桶 4；混合 `[1,3]` 选择 PIECEWISE，桶 4；`[9]` 超出桶集合，NONE。课程不检查分段 wrapper 的准备状态，不代表第二种情况已经真实捕获成功。取消完整图 `{4}` 后，第一种也回到 NONE。

</details>

## 14. 设计一份可信的 runner 比较

准备比较两个 runner 的速度。请列出四项必须相同的条件、两项应分开计时的阶段，以及一项正确性检查。设计文档与源码能力不一致时怎么办？

<details><summary>参考答案</summary>

同一支持两条路径的提交、同一硬件软件环境、模型精度、输入与输出负载必须固定；图模式及实际命中也要对应。首次加载/编译/捕获与预热后运行分开，主机准备、同步和前向应明确计时边界。正确性至少核对请求归属、输出长度和约定的数值容差；随机采样还要控制策略。设计文档说明动机，能力结论要结合固定源码与实机证据；未验证和明确不支持要分开记。

</details>
