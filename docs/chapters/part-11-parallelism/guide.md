# 并行、MoE 与分离式部署：先画清楚数据分工

对应 6.5、11.1—11.7、11.9、12.1—12.2、12.5、13.1、13.6、13.9、13.12。前置：矩阵乘、缓存、调度。状态：**推导与源码导读已提供；分布式实现和实机测量待完成**。

吸收 vLLM 第 12—15、19 讲，SGLang 第 15 讲与测试手册。首批硬件仍是各自单卡 A100/C500；下面的多设备例子用于推导，需要额外同栈设备才能做通信实验。

## 1. 每种并行究竟切了什么

| 策略 | 分工维度 | 典型代价/需要核对的内容 |
| --- | --- | --- |
| TP | 层内张量，常见是线性层/头维度 | partial sum 合并、激活通信、KV 复制 |
| PP | 模型层 | 跨 stage 激活传递、流水线气泡 |
| DP | 请求和模型副本 | 路由、排队；Dense 与 MoE 的组关系不同 |
| EP | 专家权重与 token 路由 | dispatch/combine、All-to-All、负载不均 |
| CP | 上下文 token/KV | 需要全局注意力信息的交换或归约 |
| PCP | Prefill 上下文计算 | Q/K/V 分工、KV 交换、因果负载平衡 |
| DCP | Decode 的历史 KV 分工 | query/部分输出通信、全局归一化 |
| SP | 与 TP 配合的序列维激活分片 | gather/scatter 与层间布局转换 |

名字不决定实际通信组。记录 rank、组成员、张量切分轴，再查所选版本如何组合；DCP/EP 可能复用已有组，不能把所有度数直接相乘得到卡数。

## 2. TP 的两个最小等式

采用 `X[M,K] × W[K,N]`，先忽略 bias。

**按输出列切**：`W=[W0 W1]`，各设备得到 `Y0=XW0`、`Y1=XW1`，按列拼接得到 Y。下游若能消费分片，不一定立刻 all-gather。

**按输入维切**：`X=[X0 X1]`，W 按行切为 W0/W1，得到 `Y=X0W0 + X1W1`。这里是求和；一般不能在各 partial sum 上先做非线性再求和。bias 也必须避免按 rank 重复累加。

练习：令 `X=[1,2]`，`W=[[1,3],[2,4]]`，完整输出是 `[5,11]`。分别做两种切分，标出 concat 和 sum 的位置，再把输出传给下一层。

TP 不一定令每卡 KV 等比例下降。KV heads 数较少、实现采用复制或模型使用压缩表示时，需要按真实布局重新计算。

## 3. PCP 与 DCP 的不同目标

Prefill 面对许多新 query token，可以把计算分配到多设备；但一个 query 的注意力仍需要它可见的 KV。可研究 gather KV 或分段传递 KV 的算法，并考虑因果三角形造成的负载不均。

Decode 每步新 query 较少、历史 KV 较长。将 KV 按上下文分片后，每个设备计算局部结果，再用一致的全局 softmax 统计合并。vLLM 的 DCP 部署说明解释了它与 TP/KV 复制的关系；度数、模型、后端和推测组合需在目标版本验证。[Context Parallel 说明](https://docs.vllm.ai/en/latest/serving/context_parallel_deployment/)

### 为什么不能直接平均各卡 Attention 输出

设备 i 保存局部最大值 `m_i`、指数和 `l_i`、未归一化加权和 `a_i`。取 `m=max_i(m_i)`，再计算：

```text
l = sum_i exp(m_i-m) * l_i
a = sum_i exp(m_i-m) * a_i
output = a / l
```

每卡的归一化分母不同，直接平均 `a_i/l_i` 通常错误。用[Attention 导读](../part-07-attention/guide.md)的两个分数分到两卡，验证答案仍是 `7/3`。

**拓扑作业**：先画 TP/PP/DP 的设备网格，再标出该版本 PCP 是否增加执行 rank、DCP 如何取组。对每个 Tensor 写 owner、shape、复制范围、通信原语；不能只提交 `TP×PP×DP×CP` 一个乘积。

## 4. MoE 从 token 路由开始

先看单层：router 选择 top-k → token 按专家组织 → 专家计算 → 按原 token 位置和权重 combine。统计的专家负载总数在普通 top-k 路由中是 `token 数 × k`，不是原始 token 数；丢弃、容量限制或其他模型机制另记。

教学例子：4 个专家、4 个 token、top-2，路由为 `(0,1)、(0,2)、(0,1)、(0,3)`。各专家接收 `[4,2,1,1]` 个 token，总计 8。

如果设备 A 持有专家 0/1，B 持有 2/3，分配数是 6 与 2，权重均分并不保证计算均分。移动专家可能平衡未来负载，也会增加传输和状态更新成本。

EPLB 阅读重点：逻辑专家与物理副本映射、窗口统计、冗余副本、迁移时序与推理并发。用“窗口内节省的关键路径时间”与“重排和迁移代价”比较，不能仅凭某次直方图不均就认定开启后更快。

## 5. DBO、TBO 与异步调度

这些机制都可能讨论重叠，但需要说清楚重叠对象。异步调度常关注 CPU 准备与设备工作；vLLM DBO 的设计目标是 MoE 的通信与周围计算交错。

当前官方 DBO 说明面向 DP+EP，并给出多 DP rank、DeepEP 后端和 token 阈值等运行条件。它不是当前两条单卡基线默认开启的开关。[DBO 设计](https://docs.vllm.ai/en/latest/design/dbo/)

SGLang 的 TBO/SBO 留作机制对照；不把它们写成 vLLM 的同名配置。微批次时间线至少包含提交、通信等待、计算、同步、合并，确认真实覆盖的空隙而不是只看到两个线程。

## 6. PD 分离要算传输账

Prefill 和 Decode 由不同实例执行。KV 数据、请求身份、模型/Tokenizer 版本、位置和采样状态必须匹配；收到传输通知不一定意味着所有可见数据都已经可安全消费。

一个教学临界条件是：阶段独立调度和计算带来的节省，应大于 KV 传输、路由、同步和额外排队代价。若某次传输 1 GiB、测得有效链路带宽 20 GiB/s，仅数据项就约 50 ms，尚未包含其他延迟。这是算式示例，不是 C500/A100 测量值。

| 阶段 | 必须明确的所有权和失败行为 |
| --- | --- |
| 生产 | 谁分配块，何时 KV 已可发送 |
| 传输 | scheduler 元数据与 worker 数据怎样对应，是否分层/异步 |
| 消费 | 谁确认完成，layout/dtype/block size/分片是否兼容 |
| 失败 | 重试、重算或返回错误，超时和取消如何回收 |
| 结束 | producer/consumer 何时可释放，是否仍有在途读写 |

旧版第 19 讲可帮助理解这些问题，具体补丁需回到所选 connector 实现核对。P1D1 即使每实例 TP1，仍占用两张设备；单卡上两个进程的模拟不证明两设备传输性能。[vLLM 分离式 Prefill](https://docs.vllm.ai/en/latest/features/disagg_prefill/)
